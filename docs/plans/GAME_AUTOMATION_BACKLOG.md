# 独立候选计划：洛克王国世界每日清体力自动化

状态：候选调研，未批准实现
最后核对：2026-07-31

## 1. 目标与当前结论

候选目标是在用户已经手动登录《洛克王国：世界》后，由用户显式启动一个可停止、失败即停、全程本地的前台“一键清体力”流程。当前只记录需求、边界和进入实现前的检查点；仓库尚未引入 MaaFramework、游戏资源、输入控制、调度器、页面或发布制品。

MaaFramework 可作为候选底座，因为它提供 Win32 控制器、截图、模板匹配、OCR、Pipeline 和自定义 Agent。MaaNTE 证明了“资源包 + JSON Pipeline + Python 自定义难点 + 通用 UI”的工程组织方式可用于同类桌面游戏自动化；RocoPilot 则展示了面向《洛克王国：世界》的 OpenCV/YOLO/SIFT 与自定义状态机方案。这些项目只作为公开架构和行为证据，不代表账号安全，也不授权复制其源码、图片、模型或其他资产。

## 2. 强制边界

- 首版只允许用户手动登录后、前台、显式一键启动；不自动登录、不保存游戏凭据、不处理验证码。
- 不修改游戏文件、内存或网络封包，不注入游戏进程，不安装或调用内核输入驱动。
- 不实现反检测、设备伪装、行为伪装或规避封禁，也不得对用户宣称“无法检测”或“零封号”。
- 首个垂直切片不提供开机启动、无人值守定时运行、远程控制或多账号并发。
- 识别不到预期场景、窗口/分辨率不匹配、弹窗未知或用户按下停止时必须立即停止发送输入。
- 截图、模板、日志和失败证据只保存在本机；默认不上传 Worker/D1，不记录账号名、角色名或聊天内容。
- 游戏自动化领域不得复用 RSS 的管理员自动化规则、Worker/D1 规则表或条目导出队列，以免扩大云端和权限边界。

## 3. 架构候选

若检查点通过，优先评估独立资源包或受控子进程：

```text
LenxTool.App
  └─ GameAutomation Host
       ├─ 启动 / 停止 / 状态 / 脱敏日志
       └─ 独立 MaaFramework 资源包或子进程
            ├─ Win32 窗口与截图
            ├─ TemplateMatch / OCR
            ├─ 每日清体力 Pipeline
            └─ 失败截图与有界本地保留
```

主 WPF 进程不得因为候选功能而默认提升为管理员，也不得在应用启动时加载大型 OCR/视觉模型或触碰游戏窗口。自动化运行时必须有独立取消令牌、单实例约束和明确终态，退出 LenxTool 时合作停止。

## 4. 进入实现前的检查点

- [ ] 核对游戏最新用户协议、运营公告和第三方工具政策，并在 UI 中给出不夸大的风险提示。
- [ ] 固定首版支持的游戏客户端、窗口模式、分辨率、DPI 与语言；不假设其他环境自动兼容。
- [ ] 由用户提供从已登录状态开始的完整清体力步骤、关键分支、弹窗和失败画面。
- [ ] 完成只截图、不发送输入的识别 PoC：定位目标窗口，识别一个入口和一个退出/完成状态，并可视化命中区域与置信度。
- [ ] 冻结最小状态机、每步超时、最大动作数、停止热键和未知场景失败策略。
- [ ] 完成许可证与分发审查，再决定 MaaFramework 是动态依赖、独立子进程还是单独资源包。
- [ ] 用离线截图语料覆盖正常、加载、弹窗、分辨率不符、识别歧义和 UI 改版；真实账号验收必须由用户主动执行。

全部检查点满足前，不创建产品页面、不承诺发布日期，也不把本候选列为当前下一里程碑。

## 5. 首个可实现垂直切片

检查点通过后的首片仅包含：

1. 用户手动登录并把游戏切到受支持窗口状态。
2. LenxTool 显示窗口、分辨率和资源版本预检。
3. 用户点击“一键清体力”后执行单条固定流程。
4. 页面持续显示当前步骤，可随时停止；未知画面、超时或动作预算耗尽时失败关闭。
5. 本地保存脱敏结果和有界失败截图；不自动重试整条流程。

验收至少覆盖：重复点击单飞、取消传播、窗口消失、窗口切换、输入焦点错误、模板误命中、OCR 歧义、未知弹窗、应用退出和失败截图清理。
