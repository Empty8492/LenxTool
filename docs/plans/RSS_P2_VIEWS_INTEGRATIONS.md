## P2 完成定义

管理员发布的内容可以按文章、图片、音频、视频和通知等形态浏览；用户可在管理员策略允许的范围内导出或投递条目；所有集成都通过统一接口、独立凭据、主机限制、失败重试和可观测状态运行；每日/每周摘要可在本机定时生成并通知。

P2 不引入 Folo 社区、关注关系、钱包、支付、移动端或完整 AI Chat。Folo 的“社交媒体”视图暂不单独实现：纯 RSS 无可靠社交实体和互动语义，相关内容先归类为文章/图片/视频，等未来有合法稳定的数据源再单独立项。

## 阶段 P2-A：内容分类与多视图

### P2-01：内容类型分类器

**目标：** 基于 enclosure、Media RSS、正文媒体和 Feed 策略得到确定的 `EntryViewKind`。

**依赖：** P1 附件模型。
**预计范围：** S。
**主要文件：** 新 `EntryViewKind.cs`、分类器、Core 测试。

**分类顺序：** 管理员显式覆盖 > 可验证 enclosure > 正文主媒体 > 默认 Article。

**验收：**

- [x] 支持 Article、Picture、Audio、Video、Notification；未知值回退 Article。
- [x] 不仅凭 URL 扩展名信任媒体类型。
- [x] 同一输入每次分类一致，可由 Feed 管理策略覆盖。

**验证：** 多附件、MIME 冲突、缺字段和管理员覆盖参数化测试。

**参考：** Folo [`tabs.tsx`](https://github.com/RSSNext/Folo/blob/773f1bfe218ac349b9fb9b5cbd982c320f6b414f/packages/internal/constants/src/tabs.tsx) 的视图分类；LenxTool 采用更小集合。

**完成记录（2026-07-27）：** Core 新增独立的 `EntryViewKind` 与纯函数 `EntryViewClassifier`。分类器只接受单独跟踪的可空显式覆盖；覆盖存在时五类值均可强制生效，非法枚举安全回退 Article。没有覆盖时，分类器按规范化 Feed 声明顺序选择首个 URL 允许且 MIME/扩展一致验证的 enclosure，随后才接受正文提取层提供的同等级结构化主媒体信号，最后回退 Article；仅 URL 扩展名、仅 MIME、冲突类型、受阻 URL 和 Unknown 都不能提升为媒体视图。此契约刻意不把既有必填、默认 `Article` 的 `FeedViewKind` 当作自动/显式哨兵，也不修改目录 schema；后续接入必须单独保存显式覆盖状态，不能把历史默认 `Article` 直接传入覆盖参数。参数化测试覆盖五类覆盖、非法值、三类媒体、多附件顺序、MIME/扩展单边证据、冲突/受阻/缺失输入、正文主媒体和重复调用确定性。聚焦 P2-01 为 20/20，Core 全量 116/116、Infrastructure 354/354 与 Release build 0 警告/0 错误通过；App/WPF 197/198，唯一未通过项是受限环境中既有真实 WPF 验收线程超时并伴随 Windows Event Log 写权限拒绝，与本次 Core-only 改动无调用关系。

### P2-03：音频与播客视图

**目标：** 展示音频条目、时长/进度并复用媒体工作台转写入口。

**依赖：** P2-01、P1 Feed-media bridge。
**预计范围：** M。
**主要文件：** 新音频 ViewModel/模板、播放适配器、阅读状态仓储、测试。

**冻结规格（2026-07-28）：**

- 音频页是资讯中心的独立惰性页签，查询固定使用 `EntryViewKind.Audio`，并复用图片流已经验证的来源/分类/日期/收藏筛选、分页 continuation 和取消代次；进入页签、选择条目或恢复筛选都不得自动访问媒体源。
- 内置播放仅接受 `FeedAttachmentClassifier` 判定为允许 URL、已验证类型且种类为 Audio 的第一个 enclosure。用户明确点击播放后，播放适配器才打开来源；切换条目、取消加载、断流和页面释放必须停止旧播放并忽略迟到事件。
- 播放器展示 Feed 名称、来源主机、声明 MIME/大小、当前位置、可用时长与状态。时长未知时不得伪造；播放失败保留条目和安全回退操作。默认不自动播放、不在后台预取，也不把远程媒体静默保存为用户文件。
- `EntryState.Progress` 对音频条目表示本地消费进度百分比（`0..100`，档案 `default`）。播放中至多每秒防抖写入，暂停、结束、切换条目和释放前刷新最终进度；重新启动后按仓储值恢复，接近结束的进度从头开始，不能把该字段同步到云端。
- “转写”只对同一已验证音频 enclosure 可用，调用现有 `IFeedMediaDeliveryService`，继承 SSRF、重定向、MIME、签名、大小、超时和取消边界；复用 entry/source 幂等键，发布既有或新建任务到 `IMediaJobInbox` 后导航到媒体工作台。播放本身不得隐式创建转写任务。
- 强制归类为 Audio 但没有可验证音频 enclosure 的条目不进入内置播放器或转写链。若原文是安全的 HTTP(S) 地址，则使用“请求外部打开 → 明确确认”两步操作；首个动作不启动浏览器，不直接打开 enclosure，也不提供静默下载。无安全原文时只展示不可用状态。
- 本阶段不增加云端字段、数据库迁移或第三方包；WPF 播放实现使用系统媒体栈并隐藏于可替换适配器后，单元测试以假实现覆盖状态机、取消、断流、寻址和恢复语义。

**实现切片：**

1. 先以失败测试冻结音频条目安全选择、显式播放、暂停/寻址、旧事件隔离和本地进度恢复。
2. 实现播放契约、WPF 适配器和组合式音频 ViewModel，保持每个切片可编译且不暴露半成品入口。
3. 以失败测试冻结转写幂等交接、媒体工作台导航和两步外部回退，再接入音频页签与无障碍名称。
4. 完成小音频、断流、取消、重启进度、900×620/200% 布局和全量回归；文档、威胁模型和测试报告与实现同提交更新。

**验收：**

- [x] 播放/暂停、进度和来源清晰；不自动下载或自动播放。
- [x] 播放进度本地保存；转写任务幂等并可进入历史。
- [x] 不支持的格式安全回退外部浏览器或下载确认。

**验证：** 小音频、断流、取消、重启进度和 WPF 手测。

**参考：** Folo Audios/转写入口；LenxTool 现有 NAudio/Whisper 流水线。

**完成记录（2026-07-28）：** 资讯中心新增独立惰性音频页签，组合现有 `FeedContentCollectionViewModel` 的 Audio 查询、来源/分类/日期/收藏筛选、稳定 continuation、取消代次和本地状态投影；进入页签或选择条目不访问媒体源。新 `IFeedAudioPlaybackService` 把 WPF `MediaPlayer` 隔离在可替换适配器后，只有显式播放才打开第一个 URL 允许、MIME/扩展一致且分类为 Audio 的 enclosure，并在适配器入口再次执行同一验证；暂停、寻址、结束、断流、切换和释放具有类型化状态，旧源迟到事件按 URL 丢弃，系统不提供时长时显示未知。播放百分比复用本地 `EntryState.Progress`，播放中最多每秒写一次，暂停/失败/结束/切换时刷新，重启从保存值恢复且 98% 以上从头开始。显式“转写”复用现有 Feed-media 安全下载与 entry/source 幂等台账，把既有或新任务发布到媒体工作台；取消不发布或导航。强制 Audio 但无已验证 enclosure、系统解码/断流失败、保留主机或自定义端口原文，只能按各自安全结果禁用或经两步确认打开，不直接打开附件或静默下载。7 项 ViewModel 测试覆盖不触网选择、42% 恢复、暂停落盘、旧事件隔离、两步回退、保留地址阻断、断流、幂等任务与取消；惰性接入、DI 和结构测试冻结页签/筛选/无障碍绑定，真实 WPF 以 1,000 条音频验证 900×620、等效 200% 缩放、无横向溢出、1～40 个可视容器和操作按钮不裁切。完整门禁为 Core 140/140、Infrastructure 380/380、App/WPF 245/245、Worker 64/64、strict typecheck、Release 0 警告/0 错误和 NuGet/npm 0 漏洞；本片无 schema、云端字段或第三方依赖变更。

**目标：** 支持 once/daily/weekly/monthly 调度、时区、错过执行和幂等。

## P2 最终检查点

- [ ] 多视图、导出队列、已选择适配器、定时摘要和通知端到端通过。
