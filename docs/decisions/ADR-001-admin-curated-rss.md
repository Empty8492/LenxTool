# ADR-001：管理员策展 RSS，普通用户只读共享目录

## 状态

Accepted

## 日期

2026-07-21

## 背景

Lenx Tools 目前只抓取固定每日早报和 13 个固定热点来源。目标不是复制一个允许每位用户自由订阅的通用 RSS 阅读器，而是由管理员维护一份共享订阅目录，普通用户只能查看管理员发布的内容。

现有系统已经有本地 SQLite/FTS5、原生 WPF 阅读器、DPAPI、Cloudflare Worker 账号/角色/审计骨架；同时现有规格明确禁止云端保存新闻正文、字幕和本地文件。

## 决策

1. Worker/D1 保存并发布共享 Feed 目录、分类、策略版本和管理员审计，是订阅配置的权威来源。
2. 管理员写端点必须由服务端 `role=admin` 校验；普通用户只能调用目录读取端点。
3. 桌面客户端根据共享目录在本地抓取 RSS/Atom，并把条目、正文、索引、图片缓存和私人阅读状态保存到本地 SQLite。
4. 普通用户不能改变共享 Feed、分类、抓取策略、规则和集成配置；默认可保存不影响共享目录的本地已读、收藏、进度与私人备注。
5. Folo 仅作为产品行为参考，不依赖其 API/SDK，不复制其 AGPL 源码和受限图标。

## 备选方案

### 每个用户自由订阅

优点：实现接近常规 RSS 阅读器，用户自主性高。
缺点：直接违背已确认的管理员策展目标；权限、内容质量和支持成本不可控。
结论：拒绝。

### 只在客户端隐藏订阅按钮

优点：改动最少。
缺点：客户端可被篡改或直接调用接口，不能构成授权；也没有共享目录和审计。
结论：拒绝。

### Worker 集中抓取并保存全部文章

优点：所有用户看到完全一致的条目，来源只被抓取一次，便于共享 AI 和邮件摘要。
缺点：改变“云端不存新闻正文”的隐私边界，增加 D1/对象存储容量、版权、内容删除和运营成本。
结论：默认不采用；若未来确有需要，另写 ADR 和数据保留/删除设计。

### 管理员导出签名 OPML，客户端只读文件

优点：无需账号服务，部署简单。
缺点：撤销、审计、增量同步、角色和多设备更新能力弱；不能复用现有 Worker。
结论：作为离线灾备/导出能力保留，不作为主路径。

## 后果

- 必须先补齐桌面登录/令牌接线和 Worker 授权测试，才能声称管理员权限有效。
- 同一 Feed 会由多个客户端分别抓取；P0 接受条目到达时间存在轻微差异。
- Feed 健康度默认是本机抓取视角；共享健康监控若要集中化，需要单独设计不保存正文的探测机制。
- D1 schema 只新增目录与策略，不新增文章正文表；威胁模型仍需加入目录投毒、SSRF 和恶意 XML。
- 现有固定早报必须以兼容迁移或内置种子 Feed 纳入新目录，不得丢失历史缓存。
