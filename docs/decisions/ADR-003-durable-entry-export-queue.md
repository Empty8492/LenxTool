# ADR-003：持久化导出队列只执行可安全重放的适配器

## 状态

已接受

## 日期

2026-07-29

## 背景

条目导出会产生本地文件或第三方远端副作用。SQLite 可以原子提交任务状态，却不能与文件系统或第三方 API 组成同一事务；如果副作用成功后应用在写回 `Completed` 前退出，重启恢复只能再次执行任务。仅靠“并发 1”或租约令牌无法提供跨系统的 exactly-once。

同时，适配器返回的远端 ID 和 URL 是不透明字符串，可能包含签名查询、临时令牌或供应商内部信息，不适合直接进入可长期查询的历史表。

## 决策

- `EntryExportRequest` 的稳定幂等键继续覆盖导出器、目标、条目、内容版本和视图类型。
- schema v21 使用 SQLite 持久化五态任务、尝试次数、到期时间、租约和封闭错误码；正文、请求/响应、凭据及任意远端 ID/URL 不进入任务历史。
- 队列只接受能力声明为 `IsIdempotent=true` 的适配器；恢复旧任务时再次校验能力，发生能力漂移则失败关闭。
- 单个客户端进程只执行一个任务；运行中按租约时长的三分之一续租。每次续租后同时读取持久取消标志，把其他进程发起的取消桥接到当前适配器；续租失败或租约丢失时取消旧执行器，数据库令牌继续拒绝过期提交。
- 适配器必须把幂等键映射为可安全重放的本地或远端操作。Markdown“新版本”文件名由幂等键派生，因此同一内容版本重试命中同一文件，不同内容版本仍产生不同文件。
- 用户取消是合作式、尽力而为：适配器尚未成功时落为 `Cancelled`；适配器已返回成功后，真实副作用优先提交为 `Completed`，迟到取消不能伪装成已撤销。
- `Retry-After` 在 0～7 天边界内原样决定下次执行时间；没有显式值时才使用指数退避。

## 备选方案

### 允许非幂等适配器进入队列，但关闭自动重试

应用在副作用前退出会丢失任务，副作用后退出又无法判断是否应重放，不能同时满足恢复与防重要求，因此拒绝。

### 只依赖长租约

无法为未知供应商耗时选择永不失效且能及时恢复的固定时长；进程暂停也可能越过租约，因此采用续租和丢失所有权取消。

### 保存完整远端 ID 或 URL

便于历史页跳转，但适配器边界无法证明不透明字符串不含秘密。P2-09 历史只承担状态审计；需要可跳转结果时，应新增按适配器类型封闭、显式脱敏的结果模型，而不是放宽现有表。

## 后果

- 新适配器接入持久化队列前必须实现远端幂等语义并准确声明能力。
- 长任务会产生有界 SQLite 心跳写入，默认十分钟租约时约每三分多钟一次。
- 历史页可以展示目标引用、条目/内容版本、状态、尝试次数、时间和封闭错误码，但不能直接从历史打开任意远端结果。
- 无法合作取消的适配器仍可能在丢失租约后完成一次调用；幂等键是跨进程和跨系统防重复副作用的最后边界。
