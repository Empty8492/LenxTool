# ADR-004：服务端邮件摘要决策闸门

## 状态

Accepted（选择 A：当前不实施，以“不扩权”关闭）

## 日期

2026-08-08；2026-08-13 接受

## 一句话建议

当前不实施服务端邮件摘要，也不收集邮箱或让 Feed 标题、摘要、正文、AI 结果进入云端。继续使用已完成的本地日/周摘要、应用内收件箱和 Windows 通知；只有在出现可验证需求且产品负责人明确批准新的隐私与运营责任后，才为“仅元数据邮件提醒”另建实现计划。真正包含内容的邮件摘要必须再立独立的服务端聚合 ADR，不能由本 ADR 顺带放行。

## 背景与已核实事实

P2-21 在桌面端按本地 SQLite 数据生成日/周摘要，使用本机 DPAPI 保存的 DeepSeek Key，结果只进入本地 `ai_reports`。P2-22 已能在摘要完成后发送默认关闭、隐私分级的 Windows 通知。当前 Worker/D1 只保存账号、目录、策略、额度和审计元数据，规格明确禁止云端持久化新闻正文、全文、AI 摘要/译文、字幕和本地文件信息。

当前 `users` 表只有用户名、密码摘要、角色和额度，没有邮箱、验证状态、订阅同意或退订记录。邮件不是“再接一个发送 API”：至少会新增邮箱 PII、验证与同意、计划、退订、投诉/退信、删除请求、域名信誉、预算和供应商数据处理等责任。

服务端发送真正的摘要只有三条路径：

1. 桌面端先生成摘要再上传。应用仍必须运行，而且本地 AI 结果会离开设备。
2. Worker 独立抓取、聚合并生成摘要。这会建立第二套抓取、调度、AI 计费、内容删除和版权链路，已经是新的服务端产品。
3. 桌面端只上报“摘要已生成”，服务端发送不含内容的提醒。它没有解决应用未运行的问题，价值与现有 Windows 通知高度重叠，却仍要求收集邮箱并运营发信系统。

因此，邮件发送 API 的接线不是当前根问题；在没有需求证据时，先引入它会扩大数据与运营面，却不能证明带来新增价值。

## 建议决策

### 当前版本

- 服务端邮件摘要：不实施。
- 邮件提供商：不选择、不创建凭据、不配置发送域。
- 邮箱：不收集，不增加 D1 字段或订阅表。
- Feed 标题、摘要、正文、AI 结果：不上传、不在 D1/R2/KV/Queues/日志/审计或邮件提供商中保存，云端保留期均为 0 天。
- 本地摘要、应用内收件箱和 Windows 通知继续作为已批准路径。
- 不新增云端文章表、邮件发送代码、定时发信任务或邮件 UI。

这不是永久否决，而是拒绝在产品价值、同意模型和数据责任尚未成立时隐式扩权。

### 重新打开闸门的最低条件

同时满足以下条件后才创建实现计划：

1. P2-21 有真实使用证据，能说明邮件解决了本地摘要和 Windows 通知没有解决的问题，并给出预期收件人数、日/周频率和峰值量。
2. 产品负责人从下文 A/B/C 中明确选择，指定预算负责人、发送域所有者和删除请求负责人。
3. 明确适用地区、隐私告知、数据处理协议、供应商区域与邮件内容保留；不能用“D1 不落库”代替对邮件队列、供应商日志和收件箱副本的评估。
4. 完成来源站点条款与版权审查。未经单独批准，不发送全文、图片、附件或大段原文；邮件必须保留规范来源链接和来源标识。
5. 先写威胁模型、迁移/回滚与费用上限，再写发送代码。

## 数据边界

| 数据 | 当前建议 | 云端保留 | 说明 |
|---|---|---:|---|
| 邮箱地址 | 禁止收集 | 0 天 | 当前账号模型没有邮箱或同意记录 |
| Feed 标题 | 禁止上传/发信 | 0 天 | 即使 D1 不保存，邮件提供商和收件箱仍会处理副本 |
| Feed 摘要/节选 | 禁止上传/发信 | 0 天 | 不把 RSS 可读取误当作可再分发授权 |
| 正文、图片、附件 | 禁止上传/发信 | 0 天 | 保持 ADR-001 的本地优先边界 |
| AI 摘要、译文、报告 | 禁止上传/发信 | 0 天 | 当前只保存在本地 SQLite |
| 私人已读、收藏、备注、路径 | 禁止上传/发信 | 0 天 | 与邮件功能无关且无必要性 |
| 订阅、投递和退订记录 | 不创建 | 0 天 | 只有批准方案 B/C 后才另行定义 |

“0 天”表示当前系统不应取得这些数据，不表示把内容交给供应商后可以保证零保留。邮件一旦送达，收件人邮箱、反垃圾系统、转发和备份的保留不受 LenxTool 控制；这是包含内容的服务端邮件与本地通知之间不可消除的差异。

## 供应商评估（仅供未来选型）

| 方案 | 当前公开成本 | 退信/退订能力 | 数据与运维影响 | 结论 |
|---|---|---|---|---|
| Cloudflare Email Service | Workers Paid 最低 $5/月；每月含 3,000 封，之后 $0.35/千封 | 自动退信/投诉抑制，允许 `List-Unsubscribe` 与一键退订头 | 与现有 Worker 最贴合，但发送仍处于 Beta；新发送域默认开启正文预览，预览约保留 7 天，必须在任何真实发送前显式关闭 | 若未来只做受控原型，优先复核此方案；当前不启用 |
| Resend | 免费 3,000 封/月且 100 封/日；Pro 50,000 封为 $20/月 | 有抑制；Broadcast 可托管退订 | 新增数据处理方；官方说明各计划邮件数据默认保留 30 天 | 不为当前需求增加供应商 |
| Amazon SES | 2026 新账号默认 Essentials 为 $0.16/千封；可切换无最低消费的 à-la-carte，出站 $0.10/千封；其他 AWS 费用另计 | 账户/租户抑制与订阅管理成熟 | 新增 AWS 账号、区域、凭据、告警和运维边界；对当前小规模产品复杂度过高 | 只有规模或稳定性证据推翻简化目标时再评估 |

价格和产品状态会变化，真正立项时必须重新查官方资料并锁定预算上限。Cloudflare 只是条件候选，不是本 ADR 已批准的供应商。

## 若批准最小元数据原型，仍必须满足的控制

以下控制只描述未来方案 B 的最低门槛，不授权实现：

方案 B 能触及的数据必须先封闭为下表，不允许实施时用“投递需要”追加任意字段：

| 数据类别 | 允许字段/形状 | 最长保留 |
|---|---|---:|
| 未验证地址 | 应用层加密的邮箱、域隔离查找 HMAC、验证令牌摘要、创建时间 | 24 小时；过期原子删除 |
| 有效订阅 | `user_id`、加密邮箱、查找 HMAC、验证/同意时间、同意版本、日/周枚举、时区、订阅状态 | 订阅有效期；退订或账户删除后 7 天内删除可逆邮箱，30 天内完成备份/Time Travel 的加密擦除证明 |
| 抑制墓碑 | 不可逆且域隔离的邮箱 HMAC、封闭原因、抑制时间 | 直到收件人主动完成新的双重确认；普通账户删除不得恢复发送 |
| 投递元数据 | 稳定投递 ID、用户/抑制主体引用、日/周枚举、UTC 窗口、封闭状态、尝试次数、供应商 Message-ID 的 HMAC、时间戳 | 30 天 |
| 同意审计 | 不可逆主体引用、同意版本、接受/撤销时间，不含邮箱 | 180 天 |
| 供应商数据 | 收件地址与必要投递状态；不得含内容预览、点击/打开事件或原始响应正文 | 供应商侧最多 30 天；无法通过合同、配置和删除演练证明时禁止上线 |

默认禁止 IP、User-Agent、设备名、打开/点击数据、原始 Message-ID、原始退信正文、任意供应商响应、主题和正文进入 D1、Queues、日志或审计。若抑制墓碑在适用地区仍被认定为个人数据，必须在隐私告知中单列其用途与保留例外；无法合法保留时，方案 B 失败关闭，而不是删除墓碑后恢复发送。

- 默认不订阅；邮箱必须由用户本人双重确认，管理员不能代订阅。
- 每封只允许一个已验证收件人，不支持任意收件人、CC/BCC、附件或用户提供的发件人。
- 邮件正文只能是通用的“本地摘要已就绪，请打开 LenxTool”，不能包含标题、来源、URL、摘要、正文、AI 结果或私人状态。
- 使用独立发送子域、SPF、DKIM、DMARC；新域渐进升量，并设置每用户、每日和全局硬上限。
- 每封都带独立摘要主题的一键 HTTPS 退订和 `List-Unsubscribe-Post`；退订无需登录、立即停止新任务，投诉和硬退信永久失败关闭，不能自动移出供应商抑制名单。
- 关闭内容预览、点击跟踪和打开跟踪；应用日志只记不含邮箱/主题/正文的封闭状态码和请求 ID。
- 原始邮箱、供应商日志、队列、备份与抑制名单的删除/保留能力、密钥轮换、失败处理和预算告警必须在实现计划中给出，并按上表通过真实删除与加密擦除演练。
- 发送任务必须幂等，供应商返回结果不明时不能盲目重发；邮件失败不能影响本地摘要和收件箱。

## 版权处理

当前建议不发送内容，因此不新增内容再分发。若未来选择方案 C，必须逐来源核对 RSS/站点条款与适用法律，并至少遵守：不发送全文、图片或附件；只使用经批准的最小标题/短节选与规范来源链接；保留来源标识；提供来源删除/屏蔽机制；AI 改写不能被当作消除原作权利的手段。该审查需要形成单独记录，本 ADR 不构成法律意见。

## 决策记录

- **已选择 A（2026-08-13）**：接受“当前不实施”。保持所有内容本地，P2-23 以“不扩权”关闭。
- **B 未批准**：不启动只含通用提示的元数据邮件原型，不收集邮箱 PII，也不建立验证、同意、退订、抑制或投递记录。
- **C 未批准**：不让标题、摘要或 AI 结果进入服务端或邮件；若未来重开，必须另立服务端聚合 ADR，不能沿用本次授权。

本决策不授权任何邮件实现、供应商选型、D1 字段、Worker 路由或桌面邮件入口。当前仓库继续只使用本地摘要、应用内收件箱和 Windows 通知。

## 后果

- 当前隐私声明、D1 schema、Worker API 和本地优先架构保持不变。
- 不产生发送域、邮箱数据库、供应商凭据、邮件费用、投诉与域名信誉负担。
- 用户在应用未运行时仍不会收到服务端摘要；这是当前建议主动接受的限制。
- 如果真实需求证明该限制不可接受，下一轮决策会有明确的价值基线和授权边界，而不是从已写好的邮件代码倒推隐私政策。
