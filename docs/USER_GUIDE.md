# Lenx Tools 使用说明

## 安装与首次启动

1. 运行 `LenxTool_Setup.exe`。
2. 安装器会静默检查 WebView2 Runtime，可选创建桌面快捷方式。
3. 首次启动会在 `%LocalAppData%\LenxTool` 创建数据库、备份、日志、模型、输出和更新目录。
4. 不需要另行安装 .NET。

便携版解压后运行 `LenxTool.exe`。便携版程序文件可移动，但用户数据库与密钥仍固定保存在 LocalAppData，以便升级和多版本共用。当前源码已完成 Gate 0、P0、P1、P2-01～P2-14 与统一发现开发验收，但现有安装制品尚未按本轮源码重新签名发布；不要把旧 `Release` 安装包当作最新正式版本。

## 全局操作

- `Ctrl+K`：打开命令面板。
- 侧栏：进入首页、资讯列表、每日早报、热点趋势、AI 报告、媒体工作台、文档与数据、历史与数据、设置；管理员登录后还会显示“订阅管理”和“自动化规则”。
- 右上角铃铛：查看本机内容命中、系统健康和任务完成三类最近通知及未读数量，可用下拉框只看某一类；筛选不会改变未读状态。点击通知可标为已读，也可一键“全部已读”。通知只显示类别、标题与来源，不保存正文、摘要结果、异常详情或外部链接，关闭软件后本机已读状态仍会保留。
- 设置可切换深色模式和减少动画；点击“保存外观”后，重启会自动恢复。

## 首页

首页只显示本机缓存，不在打开页面时直接请求新闻网站。顶部状态会汇总 ACTIVE Feed、热点、媒体任务和收藏计数；左侧早报卡片直接从最新一期每日早报的“概览”开始，最多显示 5 个栏目、每栏 3 条，点击“查看完整早报”直接进入“每日早报”。Feed 与旧版本 `news_articles` 仍会按规范 URL 或内容指纹去重。

空目录时，管理员进入“订阅管理”并点击“新建 Feed”，表单会预填兼容种子 `https://daily.juya.uk/rss.xml` 和“每日早报”。仍需点击安全发现并完成目录写入；普通用户不会获得目录写入口。断网时首页继续显示本地缓存，空库会提示可添加的兼容 Feed 地址。

## 共享账号

共享账号需要部署方先配置 Worker 的 HTTPS 根地址。开发环境可在启动应用的同一个 PowerShell 窗口中执行：

```powershell
$env:LENXTOOL_WORKER_BASE_URL='https://<your-worker-host>'
dotnet run --project src/LenxTool.App/LenxTool.App.csproj
```

`LENXTOOL_WORKER_BASE_URL` 不是密钥；地址缺失或不是 HTTPS 时，应用保持离线可用并禁用登录按钮。配置后进入“设置 → 共享账号”，输入用户名和密码登录。密码在每次登录尝试后立即从界面状态清空；短期 access token 只驻留内存，refresh token 使用 Windows DPAPI CurrentUser 写入 `%LocalAppData%\LenxTool\Secrets\secrets.dat`，不会进入 SQLite 或日志。

登录后设置页显示角色和当日 AI/语音额度，侧栏显示账号状态。只有 Worker 返回 admin 角色时才显示“订阅管理”；客户端隐藏入口只改善体验，每个管理请求仍由 Worker 重新授权。点击“退出”会先清除本地会话；即使 Worker 暂时离线，本地 access token 也不会继续保留。

共享目录会在启动恢复账号后、每次登录后立即同步，成功后约每 15 分钟检查一次。设置页“共享账号”卡片会显示目录版本、最后成功同步时间和“已是最新/已过期”状态。断网或 Worker 超时时应用继续使用最后一次完整目录并自动退避重试，不会清空已缓存目录；首次登录尚未成功同步时会显示“共享目录尚未同步”。普通用户只会读取启用目录，管理员可同步包含停用项的管理目录；客户端同步链路不会发出任何目录写请求。

Feed 发现服务默认只访问公网 HTTPS/443。部署方确需 HTTP Feed 时，可在启动应用前把精确主机名加入逗号分隔的 `LENXTOOL_FEED_HTTP_HOSTS`；确需 RFC1918/ULA 内网 Feed 时，另加入 `LENXTOOL_FEED_PRIVATE_HOSTS`。内网 HTTP 主机必须同时出现在两项配置中；不支持通配符、URL 或自定义端口。管理页可以预览被本机策略允许的 HTTP Feed，但 Worker v1 目录仅接受 HTTPS，因此此类预览暂时不能保存。

本地解析层已支持 RSS 2.0 与 Atom，并识别常见日期、作者、分类和音视频 enclosure。兼容测试覆盖 20 个独立样本，包括中文、ISO-8859-1、UTF-16 大/小端、CDATA、相对链接和常见扩展命名空间。条目正文会转换为纯文本且不执行 Feed 内脚本；`file://`、`javascript:` 等链接不会进入条目。条目身份会优先使用发布方 id/guid，并在缺失时使用规范 URL 或 Feed 作用域内容指纹，因此重复抓取不会因抓取时间产生新身份。

本地客户端会在启动后刷新已同步目录中到期的启用 Feed，并按照目录配置的 5～1440 分钟间隔再次抓取。服务器支持时会发送 ETag/Last-Modified，未变化的 304 不重写本地条目；单个来源失败不会阻塞其他来源，系统会自动延迟重试且最长退避 6 小时。关闭应用会取消尚未结束的抓取。

进入左侧一级菜单“资讯列表”后，左侧列表默认显示全部启用目录的最新缓存，每页 50 条；滚动接近底部会自动加载下一页，也可按 Tab 键聚焦“继续加载”。顶部可组合选择分类、Feed、发布日期和关键词，点击“应用筛选”从第一页重新查询；“清除筛选”恢复全部条目。列表只物化当前页并使用回收虚拟化，1 万条缓存不会一次创建 1 万个界面项。

选择条目后，右侧复用每日早报的原生只读阅读器，不执行 Feed 脚本，也不会自动打开外链。阅读器会显示当前是“RSS 正文”还是“提取全文”；全文缓存可用或该 Feed 允许打开时提取时，默认显示提取全文及提取时间，并可随时切回 RSS 正文。提取失败、离线或策略关闭时始终保留 RSS 正文。“在浏览器打开原文”只把当前条目的无凭据 HTTP/HTTPS 地址交给系统浏览器，`javascript:`、`file:` 和带用户名/密码的 URL 不会打开。页面状态会显示最后抓取和目录同步时间；断网或同步失败时标记为“离线缓存”并继续展示本地内容。资讯列表没有新增、编辑、删除或订阅管理入口，普通用户不能通过该页面修改共享目录。

正文图片会优先读取本地缓存；缓存未命中时只允许经过本机 Feed 网络策略批准的 HTTP/HTTPS 目标，并限制逐跳重定向、并发、每篇资源数和总下载字节。公网 HTTPS 主机名可兼容 Clash/sing-box 常见的 `198.18.0.0/15` Fake-IP DNS 映射，但直接访问该保留网段仍会被阻止。SVG、MIME 与文件签名不一致或超限内容会显示占位提示，不会写入缓存。完全离线时已缓存图片仍可显示；同一未缓存图片失败后短期内不会反复请求。

RSS enclosure 与 Media RSS 附件会显示在阅读器底部，每项标明图片/音频/视频、文件大小或“大小未知”、类型校验状态和“外部来源，打开前请确认”。普通浏览时，只有 MIME 与扩展名匹配、已知不超过 12 MiB 的 HTTPS 图片会通过既有安全图片缓存链路预览；音视频、大图、未知大小和不支持的格式不会自动下载，可在确认后交给系统浏览器打开。管理员明确发布的 `SendToMedia` 规则命中后，受支持的音视频可在后台经同一逐跳地址校验、类型/容器/大小/超时限制下载到专用临时目录，成功后才进入媒体工作台；失败或取消不留半成品任务。`file://`、带账号信息、自定义端口、私网或回环字面地址等目标会显示“地址已阻止”，且不会生成可点击链接。

Feed 条目已进入统一本地全文索引。180 天清理边界会保护已有收藏、标签和 `user_entry_states` 私人状态；当前仍不会在后台自动执行。首次打开未读条目会自动标记已读，阅读器按钮随后显示“标为未读”，可手动恢复；时间线也可切换已读/收藏并显示本机进度。筛选栏可选择全部/未读/已读、勾选“仅看收藏”，再按一个本机标签筛选，这些条件可与分类、Feed、日期和关键词组合，点击“清除筛选”可一次恢复。选择条目后，阅读器顶部可编辑最长 4000 字（支持换行）的私人备注，输入最长 80 字的标签并添加，已有标签可从当前条目移除；“取消”只还原当前已保存的备注，“保存备注”不会自动收藏条目。阅读正文时滚动位置会在短暂停止后自动保存，重新选择或重开同一条目会恢复位置，点击“从头阅读”可清除进度并回到正文顶部。全局搜索的 Feed 结果右侧也提供同一组收藏、已读、备注和标签入口。保存状态会明确显示，所有数据只写入本机，不修改共享目录。

## 管理共享订阅

以管理员账号登录后进入“订阅管理”，先点击“刷新目录”取得最新 ALL 快照。页面的“分类”和“Feed”标签分别提供列表与编辑器：可以新增或选择现有项目，修改名称、启用状态、刷新间隔和排序，也可以用上移/下移按钮调整顺序。删除需要先点“准备删除”，再执行第二次确认；删除目录项不会删除已经缓存在本机的文章。

“发现”标签可在同一输入框搜索关键词、站点/Feed URL 或受支持的 RSSHub 路由。候选显示规范化地址、来源、健康、警告和本机最多 4 条真实近期预览；预览只读取本地标题与时间，不上传正文。点击“加入共享目录”后还会单独显示分类、刷新、视图和全文策略，必须勾选“我已核对”才能确认发布。规范化地址已经存在时按钮会变为“查看现有项”，不会再次写入；HTTP 候选可以预览，但当前 Worker 目录只接受 HTTPS。

发现页发布使用当前 ALL 目录版本。其他管理员抢先写入时，页面只刷新最新目录并要求重新核对，不会自动重放；网络中断导致结果未知、或远端成功但本地未刷新到新版本时，发布会暂时锁定，必须先点击“刷新目录”确认状态。成功刷新后，当前候选会立即转为“查看现有项”。客户端仍不是授权边界：普通用户即使绕过界面构造写请求，Worker 也会返回 403。

Feed 的“视图类型”默认选择“自动识别”，客户端会根据经过 URL、MIME 和扩展一致性验证的附件分到文章、图片、音频或视频。选择“文章”“图片”等具体类型表示管理员强制覆盖；强制“文章”与自动识别是两个不同状态，适合修正附件声明异常的来源。

分类和 Feed 编辑器都提供“AI 处理策略”。可以分别允许、关闭或继承上级的手动摘要、自动摘要和自动翻译，并覆盖翻译语言、每日处理条目上限与并发上限；Feed 设置优先于分类，分类再继承全局安全默认。编辑器会显示解析后的最大条目数、自动任务数和并发估算。自动摘要与自动翻译默认关闭；管理员明确启用后，新抓取条目会在本机持久化排队并后台处理，关闭策略或停用 Feed/分类会在下一次模型调用前生效。每日上限按每个 Feed 的不同条目计数，摘要和翻译共享同一条目名额；达到上限会顺延到下一 UTC 日。失败任务自动退避，关闭或重启软件后可从持久化队列恢复。

自动处理生成的摘要和译文只保存在本机 SQLite，不上传共享目录或 D1。相同内容哈希、目标语言、模型与提示版本会先命中本地缓存，不会重复调用；正文或翻译语言改变后旧任务会自动失效。存在自备 DeepSeek Key 时优先直连且不消耗共享额度；没有 Key 时使用已登录账号的共享额度，普通用户余额不足会在发出模型请求前阻止，管理员继续遵守 Worker 的服务端规则。

新增或修改 Feed URL 时，必须先点击“验证 Feed”。安全发现完成后会显示标题、站点、RSS/Atom 类型和警告；只有当前输入 URL 与已验证 URL 完全一致、并满足 Worker HTTPS 约束时才能保存。改动 URL 会立即清除预览并要求重新验证。

每次保存都基于页面显示的目录版本。如果其他管理员先完成了更新，页面会刷新最新目录并提示重新核对，不会自动覆盖对方修改。若远端写入成功但本地刷新失败，页面会明确显示已提交的新版本并暂时禁用继续写入；点击“刷新目录”恢复到最新版本后再操作。退出登录或角色被降级时，管理目录会立即清空。

“OPML 导入/导出”标签提供三步导入：先点“选择并预览”读取 `.opml`/`.xml`，检查新增、重复、冲突和无效项，再勾选需要的新项，最后点“验证并原子导入”。选择文件本身不会写入目录；嵌套分组会展平为“父 / 子”分类。提交前客户端会逐项执行与单个 Feed 相同的 DNS、重定向、响应大小和 XML 安全验证，并复核最终 URL；任何选中项失败时本批不提交。一个批次最多包含 100 个分类和 Feed 操作，成功只增加一次目录版本。

点击“导出目录”会导出当前管理员 ALL 快照中的共享 Feed、站点 URL 和分类；停用项也会保留，以便完整备份。导出文件不包含用户名、令牌、API Key、文章正文、ETag、失败诊断或本地阅读状态。OPML 文件最大 2 MiB，DTD/外部实体和过深/过多 outline 会被拒绝；导出采用临时文件完成后替换，生成失败不会截断已有目标文件。

“健康”标签会读取本机全部目录 Feed 的抓取状态，包括停用项。每行显示最后成功、最后失败、连续失败次数、下次抓取时间和固定错误类别；页面不会显示令牌、完整响应、内网地址或解析堆栈。对仍启用的 Feed 可点击“立即重试”，同一按钮执行期间不能重复提交，重试会继续使用原有地址安全校验、大小/超时限制、解析限制和单 Feed 并发门闩。

## 管理自动化规则

以管理员账号登录后，左侧会显示“自动化规则”；普通用户和未登录状态没有此入口。先点击“刷新规则”读取最新规则集，再选择已发布规则或点击“新建”。编辑器只提供固定字段、当前字段允许的操作符、匹配值和受限动作：布尔值与翻译语言使用固定选项，页面不接受脚本、自定义网络请求或通知 URL。

点击“只读模拟”会在本机最近 20 条资讯上展示命中、未命中和计划动作。模拟只读取本地条目与目录，不会写规则运行账本或动作队列，也不会调用 AI、下载媒体或产生通知。编辑任何条件或动作都会清除旧模拟结果，避免把过期结果误认为当前草稿。

点击“发布新规则”或“发布新版本”才会向 Worker 提交。发布基于页面显示的规则集版本并携带幂等键；若其他管理员已经发布，页面会刷新最新版本并要求重新核对，不会自动覆盖或重放旧草稿。服务端会再次验证管理员角色、字段/操作符/动作白名单和载荷上限，并为成功发布保存不可变版本与最小审计记录。

普通用户登录后只同步启用的 ACTIVE 规则；客户端在 Feed 成功写入后用同一规则版本做本地确定性匹配，并把命中、抑制原因和计划动作写入本机运行账本。允许动作仅包括添加标签、隐藏、标为已读、生成摘要、翻译、投递媒体和应用内通知；没有脚本、自定义命令或任意网络请求。动作使用稳定幂等键和可恢复租约，重启、重复抓取或通知订阅者异常不会重复产生副作用；临时失败按受限策略重试，达到上限后进入可诊断终态。

顶部铃铛属于应用内通知收件箱，不是 Windows 系统通知。勿扰时段、受控深链和 Windows 通知计划在 P2 实现。

## 资讯、早报与趋势

“资讯列表”“每日早报”“热点趋势”和“AI 报告”都位于左侧一级菜单，不再需要先进入资讯中心再切换标签。进入“每日早报”时默认显示当天内容；需要查看历史早报时，在右上角“选择日期”下拉框选择已有缓存日期。若当天没有缓存，页面会自动选择最近一个可用日期。正文使用原生 WPF 富文本视图，可按原始顺序显示正文配图、标题、列表和可点击链接，不依赖 WebView2。

“资讯列表”内可在“时间线”“图片”和“音频”之间切换。图片页首次打开时才读取对应条目，可按分类、Feed、发布日期和收藏筛选；每行固定三张卡片，继续向下滚动会分页加载。缩略图只走受控下载与本地缓存，离线、超限、类型不符或损坏时显示稳定占位；按 Enter 或点击卡片只会用系统浏览器打开安全的 HTTP/HTTPS 原文。

音频页同样在首次打开时才读取本地 Audio 条目，进入页面或选择播客不会自动播放、预取或创建转写任务。选择条目后可查看 Feed、来源主机、声明类型/大小、当前位置和可用时长；点击“播放”才连接已验证音频源，暂停、切换条目、断流或退出时会把进度保存在本机，重新打开可从断点继续，接近结尾的内容会从头开始。“转写”会在明确点击后按既有安全下载边界创建或复用同源任务，并切换到媒体工作台。不支持的格式或系统解码失败不会直接下载附件；“打开原文”还需在页内第二次确认，且只交给默认浏览器处理安全 HTTP/HTTPS 原文。

视频页不会嵌入网页或远程视频播放器。列表和详情只显示经过安全图片链验证/缓存的封面、Feed、原文/视频来源、声明类型/大小和“时长未知”；没有可信封面时显示稳定占位，选择条目不会探测媒体。点击“打开原文”需要第二次确认，并且打开的是安全原文而不是视频附件。点击“下载并转写”会先检查同源任务、512 MiB 上限和目标磁盘：小型已知文件可直接进入明确下载操作，未知大小或至少 20 MiB 的文件会显示声明大小、最大值、可用空间和固定目标目录并要求再次确认。执行前会重新检查，下载中可点“取消下载”；只有签名、空间和本机 Media Foundation 音轨兼容性均通过的本地文件才进入媒体工作台，失败或取消不会留下任务。

这些页面使用贴右侧的单一整页滚动条。应用内所有滚动区都统一为每日早报的 1.45 倍滚轮灵敏度，并以短促平滑过渡移动；普通整页滚动和“回到顶部”都由合成层完成视觉补间，复杂热点页面也不会为每个动画帧重新布局。快速连续滚动会在同一轨迹上累积目标，不会逐格停顿或每格重新起步。列表和下拉框使用 Recycling 像素虚拟化，并预留前后一屏项目作为平滑滚动缓冲；累计距离超过缓冲范围时会自动切换到安全滚动，不会穿过尚未创建的项目。每日早报只创建视口附近的正文段落和图片，长文不会在进入页面时一次生成全部视觉；滑离较远区域的图片会停止后台加载。切换任一一级资讯入口时会自动回到页面顶部；向下阅读超过约 180 px 后，右下角“回到顶部”按钮才渐显，点击后以约 420 ms 的缓动返回顶部。启用系统“减少动画”时会保留相同滚动距离，但取消滚轮与回顶过渡。

“热点趋势”按平台分成两列卡片，每个平台使用自己的 1、2、3……排名，不再把多个平台的相同名次交错排列。顶部来源胶囊默认全部选中；点击任意平台可隐藏或恢复对应卡片，右侧显示“已显示 N/13 个来源”，“全选”可一键恢复。来源筛选也会限定“生成趋势报告”使用的数据范围。平台卡只在进入当前视口和半屏缓冲区后创建内部热点按钮，离开较远区域会释放，因此 13 个来源不会一次生成 130 个按钮。鼠标停在卡片或标题上仍可直接滚动整页；热点条目具有悬停、按下和键盘焦点反馈，点击后只允许通过系统浏览器打开 HTTP/HTTPS 原文。

当前刷新 13 个来源：知乎、抖音、bilibili 热搜、华尔街见闻、贴吧、百度热搜、财联社热门、澎湃新闻、凤凰网、今日头条、微博、GitHub 和 Hacker News。前 11 个平台参考 TrendRadar 默认配置，数据通过 NewsNow API 获取；单个平台失败时保留该平台上一次缓存，不影响其他平台。

旧版本保存的纯文本早报缓存需要点击一次“刷新今日资讯”才能补齐图片和链接；刷新会同时更新早报与趋势。富文本正文会持久化，配图仍从来源站点加载，因此完全断网时正文可读，配图会显示加载失败提示。

### AI 解读与趋势报告

1. 在“设置”中填写自备 DeepSeek Key，并点击“加密保存”。
2. 在“每日早报”页点击“生成 AI 解读”，可分析当前选中日期的早报。
3. 在“热点趋势”页点击“生成趋势报告”，可汇总当前缓存热点。
4. 在“AI 报告”页查看报告正文、模型、生成时间和 token 用量。

报告请求可取消，生成结果和用量仅写入本地 SQLite，并可被全局搜索检索。模型输出按纯文本显示，不执行 HTML、脚本或其中的指令。AI 可能产生错误，请结合原始资讯核验。

“加密保存”在输入为空时保持禁用；输入 Key 后启用。成功后输入框会立即清空，状态显示“已配置 · 已加密保存”。Key 由 Windows DPAPI CurrentUser 加密写入 `%LocalAppData%\LenxTool\Secrets\secrets.dat`，不会写入 SQLite、日志或文档。点击“清除”会同时删除 Groq 与 DeepSeek Key。

## 媒体工作台

媒体任务既可由用户手动导入文件/SRT，也可由管理员 `SendToMedia` 规则从 Feed 的已验证音视频附件创建。Feed 来源任务会保存条目、Feed、附件和任务 ID 的本地追踪关系；下载或应用重启后仍由同一持久队列恢复，后续转写、翻译、导出和历史操作与手动任务一致。

### 使用 Groq

1. 打开“设置”，在“自备 Groq Key”中输入 Key 并点击“加密保存”。
2. 回到媒体工作台，识别方式选择“Groq Whisper”。
3. 点击“导入媒体 / SRT”，可多选音频或视频。
4. 点击“开始任务”。长音频会自动重叠分片。
5. 完成后点击“打开输出目录”。

### 使用本地 Whisper

1. 准备兼容 whisper.cpp 的 `ggml-*.bin` 模型。
2. 点击“导入模型”。应用会复制模型到 `%LocalAppData%\LenxTool\Models` 并计算 SHA-256。
3. 选择“本地 Whisper”与模型后开始任务。

模型不会被上传，也不会进入安装包。本地识别依赖 CPU 和模型大小，首次加载大型模型可能较慢。导入媒体后任务立即以“Queued”状态写入数据库；可随时点“取消”，失败或取消的任务可在最近任务中点击“重试”。

### 导入已有 SRT

1. 点击“导入媒体 / SRT”，选择一个或多个 UTF-8 SRT；可与媒体文件同时选择。
2. 应用会保留文件中的原序号、时间轴和多行正文，并创建 `Completed / ImportedSrt` 字幕任务。
3. 任务和全部字幕片段会在同一 SQLite 事务中保存；关闭应用后可在媒体工作台恢复最近任务。

支持带 BOM 的 UTF-8、中文、空格和 Windows 长路径。若序号、时间轴或正文损坏，页面会显示具体错误行且不会留下半个任务；修正文件后可重新导入。

### 翻译与导出字幕

1. 在“最近任务”选择已完成转写或已导入 SRT 的任务。
2. 输入目标语言和 DeepSeek 模型，点击“翻译 / 继续”。进度、已完成片段和 token 会逐批保存；可随时点击“取消翻译”。
3. 失败或取消后仍选择同一任务，再点“翻译 / 继续”即可从保存的断点恢复，已完成批次不会重复请求。
4. 在“导出格式”选择原文 SRT、译文 SRT、双语 SRT 或纯文本 TXT，点击“导出所选格式”。译文尚未完整生成时，仅原文 SRT 可导出。
5. 点击“打开输出目录”定位生成文件。所有格式使用 UTF-8 无 BOM，默认保存在 `%LocalAppData%\LenxTool\Output`。

字幕翻译使用“设置”中通过 DPAPI 加密保存的 DeepSeek Key；Key 不会写入 SQLite、字幕文件或模型提示。重新导出只读取本地 SQLite，不会再次调用模型。

## 历史与数据

- “全局搜索”页签可搜索已缓存的 Feed、早报、热点、AI 报告、字幕、标签和收藏；输入关键词后按 Enter 或点击“搜索”。
- 可按实体类型、起止日期、Feed 分类、Feed 来源、标签和“仅看收藏”组合筛选；结果超过一页时点击“加载更多”。结束日期包含当天。
- 选择结果可查看摘要、来源和缓存时间；有来源地址的早报或热点可用系统默认浏览器打开，应用只接受 HTTP/HTTPS 链接。

- “恢复备份”会先备份当前数据库、验证所选备份，再执行恢复。

### 本地存储与安全清理

- 设置页会在主窗口显示后后台统计数据库（含 WAL/SHM）、图片缓存和本地模型占用，不会阻塞启动。
- 点击“刷新占用”可重新统计；点击“预览清理”只计算候选，不会修改文件或数据库。
- 默认候选是严格早于 180 天，且没有收藏、备注、标签、私人阅读状态或活动任务引用的 Feed 内容。
- 预览完成后必须再次点击“确认清理”才会执行；点击“取消”不会修改本地内容。执行期间取消会停止后续批次，已完成的安全批次不会回滚。
- 图片缓存继续受全局预算与 LRU 控制；数据库空间不足或正被占用时会保留已完成清理并跳过压缩，可稍后重新运行。

## 常见问题

- 认证失败：重新保存 Groq Key，确认 Key 未过期且有模型权限。
- 429：等待页面显示的 Retry-After，或切换本地 Whisper。
- 断网：资讯显示缓存；Groq 不可用，本地工具和本地 Whisper不受影响。
- AI 报告认证失败：在设置中重新保存 DeepSeek Key，并确认账号余额和 `deepseek-v4-flash` 模型权限。
- 视频无法转换：确认 Windows Media Foundation 支持其封装与编码；可先转为 WAV/MP3。
- 本地模型失败：确认文件名是 `ggml-*.bin`、文件完整并与 Whisper runtime 兼容。
- Word 转 PDF 不可用：安装桌面版 Microsoft Word，或由未来的 `IDocumentConverter` 适配器接入其他引擎。

## 外部集成策略与个人凭据

- 管理员登录后可从侧栏进入“外部集成”，逐类启用或停用集成。Obsidian 和 Eagle 都不填写主机：前者只写本地 Vault，后者只允许客户端另行保存数字 loopback HTTP 端点。Zotero 必须填写精确主机 `api.zotero.org`，Readwise 必须填写精确主机 `readwise.io`；其他网络集成也必须填写各自精确目标主机。主机不能包含协议、端口、路径、通配符、IP、localhost 或 `.local`。
- 普通用户不能进入或调用共享策略写入。Worker 只向普通用户提供 ACTIVE 策略，ALL 与发布操作仍由服务端管理员角色校验，客户端隐藏入口不是授权边界。
- “设置 → 个人外部集成”只在本机保存尚未提供专用设置卡的通用网络类型 TargetId 与 HTTPS 地址。凭据保存后立即清空输入框，不支持明文回读，并由 Windows DPAPI CurrentUser 加密；删除凭据不会改变共享策略。选择 Readwise 后该卡会把 TargetId 固定为 `default`、端点固定为只读 `https://readwise.io/`，token 使用 `Readwise/default` DPAPI 槽位。Obsidian、Eagle 和 Zotero 使用各自的本机设置卡；Eagle 不需要凭据，Zotero API key 只使用固定 `Zotero/default` DPAPI 槽位。
- 通用网络类型的“测试连接”会先校验管理员策略、精确主机、HTTPS/443、凭据和 DNS 公网地址，再应用 8 秒超时与 30 秒冷却。Readwise 只调用无写入副作用的官方 auth 端点；Zotero 继续经过该共享边界，并额外核对个人库 User ID 与 write/按需 notes/files 权限。当前表单必须先保存，避免测试另一代目标。Eagle 使用独立的 loopback 探测，不走公网 DNS 白名单。界面只显示固定状态，不显示第三方响应、异常、请求头、token、API key 或资源库路径。
- 当前生产已注册的适配器为 Obsidian 本地文件导出、Eagle 本机 Web API 图片导出、Zotero Web API v3 个人库导出和 Readwise Reader 导出；Cubox 等其余外部服务适配器仍未安装，不会静默发出第三方请求。

### 导出到 Obsidian

1. 管理员先在“外部集成”中启用 Obsidian。该本地类型不需要目标主机；Eagle 同样使用空主机策略，Zotero 与其他网络类型仍必须配置各自精确主机。
2. 在“设置 → Obsidian Markdown 导出”中选择一个已存在的本地 Vault 根目录。不能直接选择磁盘根目录，也不能选择 UNC、网络共享、设备路径或经过 junction/symlink 的目录。
3. 可填写 Vault 内相对子目录、逗号或换行分隔的标签、可选 Markdown 正文模板，并选择是否包含来源链接。模板最多 64 KiB，只支持 `{{title}}`、`{{content}}`、`{{source_url}}`、`{{author}}` 和 `{{published_at}}`，且每种占位符最多出现一次。单条实际输入最多 8 MiB，最终 UTF-8 文件最多 12 MiB。
4. 保存设置后回到资讯阅读器，在目标条目的行内按钮或详情区点击“导出到 Obsidian”。该按钮只加入持久队列；后台执行前会重新读取当前设置和 ACTIVE 策略。同一规范化设置与内容版本会去重；Windows 路径大小写、分隔符或尾随分隔符的等价写法不会制造重复作用域。修改实际 Vault、子目录、模板、标签或来源链接开关后，再次点击会按新配置入队；仍等待执行的旧配置任务不会跨作用域写入，而会以不可自动重试的配置冲突结束。

导出始终为当前内容版本创建确定性新文件，不覆盖 Vault 中已有文件，也不读取 Vault 内模板文件。Feed 中看似 Markdown 图片、链接、自动链接或自定义 URI 的文本都会安全转义，不会自动加载或执行；内联代码与代码块会保留字面内容，并按内容选择安全反引号边界。HTML 深度、节点数、渲染工作量和最终字节数均有上限，渲染成功前不会创建目标目录或复制缓存图片。启动应用、刷新 Feed、选择条目或保存设置都不会写入；当前版本不安装 Obsidian 插件、不启动 Obsidian，也不实现或调用 `obsidian://`。配置无效、策略撤销、只读目录或路径安全检查失败时，任务会失败关闭并保留可诊断状态；暂时的本机设置存储或 Vault I/O 故障会按可重试错误处理。失败或取消的任务可再次点击显式重试，已完成的同配置任务仍保持去重。

### 导出图片到 Eagle

1. 管理员先在“外部集成”中启用 Eagle。Eagle 策略不填写目标主机；任何非空主机都会被 Worker 拒绝。
2. 在 Windows 上启动 Eagle 4.0 Build 21 或更高版本，并打开要接收图片的资源库。LenxTool 使用 Eagle Web API V2，不会安装插件，也不需要 API Key。
3. 在“设置 → Eagle 图片导出”保存带显式端口的数字 loopback HTTP 根地址。默认值为 `http://127.0.0.1:41595/`；`localhost`、公网/局域网地址、HTTPS、路径、查询、片段和含凭据地址都会被拒绝。保存设置本身只写本机配置；ACTIVE 策略启用时才会继续测试 Eagle 应用版本和当前资源库。
4. 回到资讯阅读器，在图片型条目的行内按钮或详情区点击“导出到 Eagle”。按钮只对 URL 允许、媒体类型已验证且属于 PNG/JPEG/GIF/WebP/BMP 的附件可用；选取首个兼容图片，声明大小和实际下载流都不得超过 12 MiB。下载后还会核对 MIME 与文件魔数。
5. LenxTool 把验证后的图片编码为 data URI 再交给 Eagle，不会让 Eagle 直接访问远程图片 URL。标题、HTTP(S) 来源和最多 32 个有界标签按确定规则映射。队列用端点与当前资源库的不透明修订共同去重；同进程保存新端点会等待活动导出结束，查询、下载或新增边界探测到资源库变化时任务会显示配置冲突。

从点击导出直到任务进入终态，请不要在 Eagle 中切换当前资源库。Eagle 官方 `item/add` 不支持指定资源库或条件写入，因此 LenxTool 的写前/写后探测不能形成原子保证：若资源库恰在新增请求窗口内切换，持续切换会被写后探测报告为冲突，但可能已经发生的写入无法撤销；切换后立即切回也可能无法识别。若出现该冲突，请检查两个资源库中的稳定条目，再在目标资源库保持打开时重新导出。也不要同时运行另一份 LenxTool 修改 Eagle 端点设置。

Eagle 未启动、端口错误、版本不兼容、没有打开资源库或响应超时只会让该导出显示固定错误，不会清空阅读内容或影响其他适配器。408、429、5xx 与无法确认是否已写入的响应可安全重试；稳定条目 ID、写前查询和 POST 后复查避免重复创建。界面、队列和异常不保存或显示资源库名称/路径、图片正文、远端响应或请求头；启动、刷新、选择条目和仅保存设置都不会自动导出。

### 导出到 Zotero

1. 管理员先在“外部集成”中启用 Zotero，并把唯一允许主机设为 `api.zotero.org`。不要填写协议、端口或路径。
2. 在 Zotero 官网创建仅用于当前个人库的 API key，并授予 library/write 权限；勾选“附带摘要笔记”还需要 notes 权限，勾选“上传首张兼容图片附件”还需要 files 权限。首版不支持群组库。
3. 在“设置 → Zotero 文献导出”填写正整数 User ID，显式选择“网页”或“期刊文章”。条目类型不会由 LenxTool 猜测；更改 User ID、类型、摘要或附件开关后必须先保存再测试。API key 保存后立即从界面清空并由 Windows DPAPI 加密，不支持回读。
4. 可选摘要笔记只使用 Feed 自带 summary，并在进入 Zotero note 前按纯文本 HTML 编码；不会导出 LenxTool 私人备注、正文、AI 私人状态或本机路径。父条目稳定映射标题、HTTP(S) 来源、single-field 作者、published/updated 日期和 Feed categories。
5. 图片附件默认关闭。启用后只选择首个 URL 允许、声明类型已验证的 PNG/JPEG/GIF/WebP/BMP；声明大小和实际下载流都不得超过 12 MiB，且响应 MIME 必须与声明和文件魔数一致。LenxTool 先创建 imported_file 子项，再按 Zotero 官方授权上传；API key 只发给 `api.zotero.org`，不会发给一次性存储地址。
6. 回到资讯阅读器，在任意 Feed 条目的行内 `Z` 按钮或详情区点击“导出到 Zotero”。启动、刷新、选择条目和保存设置都不会自动导出。每个内容版本、目标代际和对象角色生成稳定 key；写前/写后身份核对与文件 `exists=1` 重放避免崩溃重试重复新增或覆盖不相关条目。

取消、超时或第三方故障不能回滚已经在 Zotero 创建的父项或附件项；任务会使用相同稳定对象继续重试，遇到不匹配的既有 key 则以冲突关闭而不会覆盖。401/403 需要检查 User ID、key 和权限；429 会尊重 Retry-After，暂时 409/5xx 可由持久队列重试。界面、历史和异常不会显示 API key 或第三方响应正文。当前自动化只证明假 HTTP 契约，尚未使用受控真实个人库完成外部写入验收。

### 导出到 Readwise

1. 管理员先在“外部集成”中启用 Readwise，并把唯一允许主机设为 `readwise.io`。不要填写协议、端口、路径或相似子域名。
2. 在“设置 → 个人外部集成”选择 Readwise。TargetId 会固定为 `default`，端点固定为只读 `https://readwise.io/`；粘贴 Readwise access token 后先保存，再点击测试连接。token 保存后立即清空并由 Windows DPAPI CurrentUser 加密，不支持回读。
3. 回到资讯阅读器，在目标条目的行内 `R` 按钮或详情区点击“导出到 Readwise”。启动、刷新、选择条目和保存设置都不会自动保存文档；只有显式点击并通过 ACTIVE 策略与凭据检查后才进入持久队列。
4. LenxTool 会发送规范来源 URL、有界标题/作者/日期、最多 32 个 Feed categories，以及详情区显示的纯文本摘要预览。摘要优先取净化正文、为空才回退 Feed summary，最多 4,000 个 Unicode 文本元素且不超过 16 KiB UTF-8；预览就是实际发送的 `summary`。不会发送完整 HTML、图片、LenxTool 私人备注、AI 私人状态或本机路径。
5. 同一精确 URL 的崩溃重放不会在 Reader 创建第二条，但这不是无副作用强幂等：Readwise 官方说明再次保存会把文档移到资料库顶部并显示绿色标记；含不同追踪参数的 URL 仍可能形成第二份。需要完全避免这类可见变化时，请先等待当前任务进入终态，不要重复点击，并在来源侧使用稳定 URL。

401/403 表示 token 或账户状态不允许请求；429 会尊重有界 Retry-After，408/5xx 和无法判断的写入结果由持久队列重试。界面、队列历史和异常不会显示 token 或 Reader 响应正文。当前自动化只证明官方 API 的假 HTTP 契约，尚未使用受控真实 token/账户完成外部写入验收。
